### 1. **title** && **abstract**

**Abstract**:
语音合成（Text-to-Speech, TTS）技术近年来取得了显著进展，但**语音可变性（voice variability）建模**仍然是一个核心挑战。同一个词语可以用不同的声音（如情感、语调、音色等）表达，传递不同的信息。

传统TTS系统主要依赖以下方式控制语音可变性：
- **说话人ID（Speaker ID）**：需要预定义，不够灵活
- **语音提示（Speech Prompt/参考语音）**：难以获取合适的参考语音，在声音创作场景中甚至不存在

相比之下，**文本提示（Text Prompt）** 提供了一种更自然、更用户友好的语音控制接口，用户可以通过自然语言描述来指定声音特征。

---

### 2. **intro**

#### 主要贡献
本文指出了基于文本提示的TTS系统面临的两大核心挑战：

| 挑战 | 描述 | 影响 |
|------|------|------|
| **一对多问题（One-to-Many）** | 文本提示无法捕捉语音中的所有细节特征，不同语音样本可能对应同一文本提示 | 导致模型训练困难，容易出现过拟合或模式坍塌 |
| **数据规模问题（Data-Scale）** | 文本提示数据集难以构建，需要人工撰写，成本高且规模小（约20K句） | 限制了研究进展和模型性能 |

PromptTTS 2通过以下创新解决上述挑战：
1. **变异网络（Variation Network）**：基于扩散模型，预测文本提示未涵盖的语音可变性信息，解决一对多问题
2. **提示生成流水线（Prompt Generation Pipeline）**：利用大语言模型（LLM）自动生成高质量文本提示，解决数据规模问题
==通过 variation network 学习 Prompt → Rreference 的映射

### 3. **method**

#### 3.1 系统架构概述
PromptTTS 2的整体架构由三个核心模块组成：
![[Pasted image 20260408105753.png|522]]
 **(a) TTS模块 (TTS Module)**
  - 展示了PromptTTS 2的整体架构
  - 输入：音素序列(Phonemes)
  - 输出：语音波形(Waveform)
  - 核心组件是Style Module（风格模块），用于控制合成语音的特征                                                                                                    
  **(b) 风格模块 (Style Module)**
  - 详细展示了如何处理文本提示和参考语音
  - 文本提示编码器：使用BERT模型提取 prompt hidden ，通过可学习的查询token (QP1...QPM) 提取固定长度的提示表示 (P1, ..., PM)                                         
  - 参考语音编码器：接收参考语音作为输入，通过可学习的查询token (QR1...QRN) 提取参考表示 (R1, ..., RN)                                                            
  - M和N分别表示提示表示和参考表示的固定长度（论文中设为8）                                                                          
  **(c) 变分网络 (Variation Network)**
  - 基于Transformer Encoder的扩散模型架构
  - 输入：提示表示(P1...PM)、带噪声的参考表示(Rt1...RtN)、扩散步骤t
  - 输出：预测的原始参考表示
  - 使用FiLM（Feature-wise Linear Modulation）来增强模型对扩散步骤的感知
  - 关键作用：在推理时，由于参考语音不可用，变分网络从文本提示表示预测参考表示，实现从高斯噪声中采样不同的声音变化性     

#### 3.2 变异网络（Variation Network）

##### 3.2.1 设计动机
文本提示无法完整描述语音的所有细节特征（如精确的音色、微妙的情感变化）。
变异网络的核心目标是：
- **建模文本提示未捕获的语音可变性信息**
- **通过从高斯噪声采样实现多样化的语音生成**


```bash
  文本提示的信息（有限）        Reference Speech的信息（完整）
       ↓                              ↓
  "一个男孩大声喊叫"  ←————→  实际的声学特征（包含音色、情绪等所有细节）
       ↓                              ↓
    Prompt表示(P)              Reference表示(R)
       ↓                              ↓
       └────────→ 变分网络学习：P → R 的映射 ←────────┘ 
```

##### 3.2.2 技术实现

变异网络基于**扩散模型（Diffusion Model）**，包含两个过程：

**前向扩散过程（Diffusion Process）**：

$$dz_t = -\frac{1}{2}\beta_t z_t dt + \sqrt{\beta_t} dw_t, \quad t \in [0,1]$$

将参考表示逐步转化为高斯噪声。

**反向去噪过程（Denoising Process）**：

$$dz_t = -\frac{1}{2}(z_t + \nabla \log p_t(z_t))\beta_t dt, \quad t \in [0,1]$$

从噪声恢复参考表示，条件为文本提示表示。

##### 3.2.3 关键特点

| 特性                    | 说明                |
| --------------------- | ----------------- |
| 训练时使用参考语音             | 编码完整语音可变性信息       |
| 推理时仅依赖文本提示            | 无需参考语音，通过采样生成多样语音 |
| 基于Transformer Encoder | 使用FiLM层增强扩散步感知    |
| L1损失优化                | 预测原始参考表示          |

#### 3.3 文本提示生成流水线

##### 3.3.1 流水线应用时机说明

文本提示生成流水线仅在 **数据准备阶段（离线）** 使用，而非训练或推断时实时调用。

| 阶段       | 是否使用流水线 | 说明                           |
| -------- | ------- | ---------------------------- |
| **数据准备** | 使用      | 离线处理原始语音数据，生成(语音, 文本提示)配对数据集 |
| **模型训练** | 不使用     | 直接使用已生成的文本提示配对数据进行训练         |
| **模型推断** | 不使用     | 用户直接输入文本提示，无需调用流水线           |


##### 3.3.2 完整流程示意

```
┌─────────────────────────────────────────────────────────────┐
│  数据准备阶段（离线执行，仅需执行一次）                           │
│  ┌─────────┐    ┌─────────────────┐    ┌─────────────────┐  │
│  │ 原始语音  │ →  │ SLU模型识别属性  │ →   │ LLM生成文本提示  │   │
│  │ (44K小时)│    │ (gender/pitch等)│    │ (20K条提示)      │  │
│  └─────────┘    └─────────────────┘    └─────────────────┘  │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  训练阶段                                                    │
│  输入：音素序列 + 文本提示 + Reference Speech                  │
│  输出：训练好的PromptTTS 2模型（含变分网络）                     │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  推断阶段                                                    │
│  输入：用户提供的文本内容 + 文本提示（直接输入，无需LLM）           │
│  输出：合成语音（无需reference speech）                         │
└─────────────────────────────────────────────────────────────┘
```

##### 3.3.3 流水线架构

该流水线结合**语音语言理解模型（SLU）** 和 **大语言模型（LLM）** 自动生成文本提示：
![[Pasted image 20260408110230.png|582]]

##### 3.3.4 四阶段生成流程

**阶段1：关键词构建**
- 针对每个属性的每个类别，让LLM生成多个描述关键词
- 例如，性别-男性："man", "boy", "guy", "dude", "gentleman"

**阶段2：句子构建**
- 为每个属性生成多个句子模板
- 使用占位符（如`[Gender]`、`[Pitch]`）强调属性位置
- 示例："Generate a voice that sounds like a [Gender] with [Pitch] pitch."

**阶段3：句子组合**
- 将描述不同属性的句子组合成完整文本提示
- 同时生成短语形式，增加多样性

**阶段4：数据集实例化**
- 根据SLU识别的属性标签，采样相应句子和关键词
- 替换占位符，生成最终文本提示

##### 3.3.5 优势
- **自动化**：无需人工撰写提示
- **可扩展性**：添加新属性只需定义类别和使用SLU模型标注
- **高质量**：LLM生成的句子语法正确、表达丰富
- **多样性**：通过关键词和模板组合实现多样化表达

### 4. **experiment**

#### 4.1 实验设置

**数据集**：
- 语音数据：Multilingual LibriSpeech (MLS) 英语子集，**44K小时**
- 文本提示：PromptSpeech（20K人工撰写）+ 自生成（20K LLM生成）
- 测试集：PromptSpeech测试集（1,305条文本提示）

**基线系统**：
- PromptTTS (Guo et al., 2023)
- InstructTTS (Yang et al., 2023)

**TTS骨干网络**：NaturalSpeech 2（ latent diffusion架构）

#### 4.2 属性控制准确性

| 模型 | Gender | Speed | Volume | Pitch | **Mean** |
|------|--------|-------|--------|-------|----------|
| PromptTTS | 98.01% | 89.66% | 92.49% | 85.98% | 91.54% |
| InstructTTS | 97.24% | 90.57% | 91.26% | 86.82% | 91.47% |
| **PromptTTS 2** | **98.23%** | **92.64%** | **92.56%** | **89.89%** | **93.33%** |

**分析**：PromptTTS 2在所有属性上均优于基线，平均提升**1.79%**，尤其在Pitch控制上提升显著（+3.91%）。

#### 4.3 语音质量评估

| 设置 | MOS | CMOS (vs. PromptTTS 2) |
|------|-----|------------------------|
| GT (真实录音) | 4.38±0.08 | - |
| GT (编解码重建) | 4.30±0.07 | - |
| PromptTTS | 3.77±0.09 | -0.191 |
| InstructTTS | 3.80±0.07 | -0.157 |
| **PromptTTS 2** | **3.88±0.08** | 0.0 |

**分析**：PromptTTS 2在语音自然度上优于基线系统，验证了变异网络不仅提升控制能力，也改善了合成质量。

#### 4.4 变异网络有效性分析

通过语音相似度评估变异网络对语音可变性的建模能力（相似度越低，可变性越高）：

| 模型 | 文本提示维度 | 文本内容维度 | TTS骨干维度 | **变异网络维度** |
|------|------------|------------|-----------|---------------|
| PromptTTS | 0.766 | 0.662 | 0.799 | - |
| InstructTTS | 0.773 | 0.718 | 0.796 | - |
| **PromptTTS 2** | **0.775** | **0.873** | **0.914** | **0.355** |

**关键发现**：
1. 基线系统在不同维度上都学到了一定的语音可变性（相似度0.66-0.80），这是不期望的
2. **PromptTTS 2的变异网络维度相似度仅0.355**，表明其有效建模了文本提示未涵盖的语音可变性
3. PromptTTS 2在其他维度的相似度更高，说明变异网络承担了主要的可变性建模职责

#### 4.5 提示生成质量评估

通过训练属性分类器评估文本提示质量：

| 训练数据集 | Gender | Speed | Volume | Pitch | **Mean** |
|-----------|--------|-------|--------|-------|----------|
| PromptSpeech (人工) | 100.00% | 96.85% | 89.58% | 84.51% | 92.74% |
| TextrolSpeech (LLM) | 98.77% | 94.18% | 93.10% | 92.80% | 94.71% |
| **我们的流水线** | **99.08%** | **97.47%** | **94.48%** | **94.48%** | **96.38%** |

**结论**：LLM生成的文本提示质量**优于人工撰写**，平均准确率达96.38%。

#### 4.6 消融实验

对提示生成流水线的消融研究：

| 配置 | 平均准确率 |
|------|-----------|
| 完整流水线 | **96.38%** |
| -Placeholder (无占位符) | 94.04% (-2.34%) |
| -Phrase (无短语) | 96.09% (-0.29%) |
| -Sentence (无句子) | 96.16% (-0.22%) |

**关键发现**：**占位符设计**对提示质量影响最大，确保属性不被遗漏或改变。

#### 4.7 扩展应用：Face2Voice

PromptTTS 2的框架可扩展到其他模态。在**人脸到语音（Face2Voice）**任务中：

- 使用CLIP图像编码器提取人脸特征
- 训练变异网络预测参考语音表示
- 相比SOTA方法SP-FaceVC：
  - 生成与面部图像更匹配的语音（31.78% vs 20.17%）
  - 不适配案例更少（27.05% vs 34.45%）
  - CMOS测试：80.88%情况下优于或等于SP-FaceVC

### 5. **conclusion**

#### 5.1 核心贡献总结

1. **变异网络**：首次针对文本提示TTS中的一对多问题提出专门解决方案，通过扩散模型实现可控的语音多样化生成

2. **LLM驱动的提示生成流水线**：自动化、可扩展的文本提示生成方法，生成质量超越人工撰写

3. **大规模实验验证**：在44K小时数据上验证有效性，属性控制准确率达93.33%，语音质量优于基线

4. **通用框架**：可扩展到Face2Voice等多模态场景

#### 5.2 理论意义

| 维度 | 贡献 |
|------|------|
| **问题定义** | 明确定义了文本提示TTS中的一对多问题，并提出了系统性解决方案 |
| **方法论** | 将扩散模型引入TTS可变性建模，展示了其在多模态分布建模中的优势 |
| **数据范式** | 开创了利用LLM生成训练数据的新范式，降低了对人工标注的依赖 |

#### 5.3 实践价值

1. **用户体验提升**：用户可通过自然语言精确控制语音生成，无需寻找参考语音
2. **开发成本降低**：自动化提示生成减少了数据标注成本
3. **应用场景扩展**：支持声音创作、虚拟角色配音、有声读物等多样化应用

#### 5.4 局限性与未来方向

**当前局限**：
- 仅使用4个属性（性别、音高、语速、音量），可扩展更多属性
- Face2Voice为初步实验，可进一步深入研究

**未来方向**：
1. 从大规模语音数据中提取更多属性，增加语音生成多样性
2. 应用到更多模态（如文本描述、情感标签、说话风格等）
3. 探索更高效的变异网络架构
4. 研究提示生成流水线的进一步优化
