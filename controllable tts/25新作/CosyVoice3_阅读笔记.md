- **来源**: arXiv:2505.17589
- **作者**: Zhihao Du, Yuxuan Wang, Qian Chen, Xian Shi, Xie Chen 等 (阿里 FunAudioLLM 团队)
- **发表**: arXiv 2025

## 1. 研究背景与问题

==录音棚环境到真实世界的迁移(in the wild)==

具体来说有三个困境：

**数据规模的天花板**：前代 CosyVoice 用了几万小时数据训练，覆盖的语种和方言有限。真实世界的语音多样性远超训练集能覆盖的范围，方言间的混合和跨语种场景了。

**可控性与自然度的矛盾**：想让模型按指令调整情感、语速、口音，往往要牺牲自然度。加了控制信号后生成的语音听着"做作"，像机器人模仿人说话而不是真人说话。

**多任务割裂**：TTS、语音克隆、语音编辑、跨语言合成……

- [?] 前两个问题确实是痛点，但"多任务割裂"更像是工程层面的问题而非研究问题

==用更大的数据、更统一的框架、更精细的后训练==，让模型直接在"野生条件"下工作，而不是试图把野生数据洗干净再喂给模型。

## 2. 方法概述

### 2.1 整体架构

![[Pasted image 20260414084122.png]]

1. **多任务语音分词器 (Multi-task Speech Tokenizer)**
 Tokenizer 的核心目的不仅是压缩音频，==更重要的是提取富含情感和发音风格的语义信息 。==

- **前向传播路径：** 输入语音 $X$ 首先经过包含 12 个带有旋转位置编码（RoPE）的 Transformer 块的 Voice Encoder$_1$ 。提取出的中间表示 $H$ 随后进入有限标量量化（FSQ, Finite Scalar Quantization）模块 。
    
- **FSQ 量化机制：** 中间表示首先被投影到一个 $D$ 维的低秩空间中，然后通过有界的 `ROUND` 操作被量化到 $[-K, K]$ 的区间内 。
    
- **Token 索引计算：** 语音 token $u_{i}$ 是通过计算量化后的低秩表示在 $(2K+1)$ 进制系统中的索引来获得的，公式如下 ：
    $$u_{i}=\sum_{j=0}^{D-1}\overline{h}_{i,j}(2K+1)^{j}$$
    
- **多任务监督注入：** 与完全自监督的离散 token 不同，该 Tokenizer 使用了 53 万小时的数据进行了强监督的多任务训练（涵盖自动语音识别 ASR、语种识别 LID、语音情感识别 SER 等）。这使得它能在 25 Hz 的低帧率下依然捕获极强的副语言（Paralinguistic）信息。


2. **核心生成管道：LLM 与 DiT**
在将文本和语音统一映射为离散 Token 后，CosyVoice 3 的生成由两个核心模型接管：
#### Text-to-Speech LLM (自回归语义模型)
- **架构升级：** CosyVoice 3 将负责粗粒度语义建模的 LLM 参数量从 0.5B (5 亿) 扩展到了 1.5B (15 亿) 
- **职责：** 它像传统的文本大模型一样工作，负责将输入的文本序列自回归地预测为上述 FSQ 模块产生的离散语音 Token 序列 。更大的参数量显著降低了字符错误率（CER）和词错误率（WER），尤其是在处理罕见词和绕口令等困难样本时 。
    

#### Conditional Flow Matching (条件流匹配模型)

- **引入 DiT 主干：** 负责将离散 Token 渲染为高保真声学特征的 CFM 模型，摒弃了旧架构，全面拥抱了扩散 Transformer（DiT, Diffusion Transformer）架构，参数量从 100M 提升至 300M 。
    
- **工程简化：** 得益于 DiT 强大的建模能力，CosyVoice 3 在架构上做出了重要的“减法”。原先复杂的文本编码器（Text Encoder）和长度正则化模块（Length Regularization）被直接移除 。语音 Token 和 Mel 特征之间的帧率不匹配问题，仅仅通过一个简单的插值（Interpolation）操作就得以解决 。

### 2.2 大规模预训练

CosyVoice 3 将训练数据量从一万小时扩展到一百万小时，包括多种文本格式，如通过文本归一化（TN）和逆文本归一化（ITN）生成的不同文本格式，以增强模型对不同文本格式的鲁棒性。

预训练的策略是：先喂海量数据让 LM 学会"什么样的语音 token 序列是合理的"，建立语音的先验分布。

### 2.3 后训练（Post-training）
**指令微调（Instruction Fine-Tuning, IFT）**：构造"指令-语音"配对数据。指令可以是：
- 情感标签（开心、悲伤、愤怒等）
- 语速描述（快一点、慢一点）
- 风格描述（新闻播报、讲故事、日常对话）
- 说话人参考音频

IFT 让模型学会根据指令调整生成策略，而不是随机输出。

**直接偏好优化（Direct Preference Optimization, DPO）**：IFT 之后模型能听指令了，但生成质量不稳定——有时好有时差。DPO 的做法是：

1. 对同一条指令，让模型生成多个候选
2. 用自动指标（说话人相似度、WER、韵律指标）给候选排序
3. 用排序结果训练模型，让模型偏好"好"的输出

==DPO 不需要训练额外的奖励模型==，直接用偏好数据优化 LM 本身，比 PPO 简单且稳定。

- [?] DPO 的偏好信号来自自动指标而非人类标注，这意味着模型优化的是指标而非真实听感。指标和听感之间的 gap 有多大？

### 2.4 多任务统一

CosyVoice 3 把以下任务统一到同一个 LM 里，靠不同的输入 prompt 区分：

| 任务 | 输入 | 输出 |
|------|------|------|
| TTS | 文本 + (可选)说话人参考 | 语音 |
| 零样本克隆 | 文本 + 3秒参考音频 | 保持音色的语音 |
| 跨语言克隆 | 文本(目标语言) + 参考音频(源语言) | 目标语言+源音色的语音 |
| 指令控制 | 文本 + 自然语言指令 | 按指令调整的语音 |
| 语音编辑 | 原始语音 + 修改指令 | 局部修改后的语音 |

- [!] 统一的关键在于：这些任务的输入都可以表示为"文本 token + 语音 token + 指令 token"的序列，LM 不需要知道自己在做哪个任务，只需要学会处理这些 token 序列。

## 3. 核心洞见

> 把语音生成当作语言建模来做——统一 token 序列 + 大规模预训练 + 后训练对齐——这条路径能通向"野生条件"下的高质量语音生成，不是因为某个模块设计精巧，而是因为规模和统一带来的涌现能力。

>[!important]
这个洞见的实质是：==语音和文本的序列建模本质相同==，NLP 领域验证的"预训练 + 后训练"范式可以直接搬到语音上
但这个洞见和 Seed-TTS、CosyVoice 2 的本质相同，CosyVoice 3 的增量贡献更多在=="规模放大"==

## 5. 实验结果

### 5.1 零样本 TTS
在 Seed-TTS 测试集上的表现：

| 模型          | WER(%) | SIM↑  | NMOS↑ |
| ----------- | ------ | ----- | ----- |
| CosyVoice 2 | 3.81   | 0.782 | -     |
| CosyVoice 3 | 2.73   | 0.817 | 4.02  |
| Seed-TTS    | 2.88   | 0.802 | 3.98  |

WER 下降 28%，说话人相似度提升明显。NMOS 超过 Seed-TTS，接近真实录音水平（4.12）。

### 5.2 跨语言克隆

| 设置 | 中文→英文 | 英文→中文 | 中文→日文 |
|------|-----------|-----------|-----------|
| WER(%) | 4.2 | 5.1 | 6.8 |
| SIM | 0.79 | 0.76 | 0.74 |

跨语言克隆的说话人相似度有下降但依然可用，内容准确度受目标语言影响较大。

### 5.3 指令控制

- 情感控制：6 种情感类别的分类准确率 87%
- 语速控制：指定语速与实际语速的相关系数 0.91
- 风格控制：新闻/对话/讲故事三种风格的区分度良好

### 5.4 消融实验

- **数据规模**：从 10 万小时到 100 万小时，WER 从 4.5% 降到 2.73%，改善呈对数线性关系
- **DPO**：去掉 DPO 后 SIM 下降 0.03，NMOS 下降 0.12
- **双码本 vs 单码本**：双码本 WER 低 0.4%，SIM 高 0.02

## 6. 同领域/同系列对比

| 方面 | CosyVoice 2 | CosyVoice 3 | Seed-TTS |
|------|-------------|-------------|----------|
| LM 骨干 | Qwen2.5-0.5B | Qwen2.5-1.5B | 未公开 |
| CFM 架构 | 原版 Flow Matching | DiT (300M) | 扩散模型 |
| 训练数据 | ~5万小时 | 100万小时 | 未公开 |
| 后训练 | 无 | IFT + DPO | 自蒸馏 + PPO |
| 核心贡献 | 流式推理 | 野生条件+规模 | 高质量多任务 |

**CosyVoice 3 的增量贡献**：
1. 数据规模扩大 20 倍（5万→100万小时）
2. 引入多任务监督的 Tokenizer（53万小时有标注数据）
3. LLM 参数量扩大 3 倍（0.5B→1.5B），降低 CER/WER
4. CFM 升级为 DiT 架构，参数量提升 3 倍（100M→300M）
5. 首次引入后训练策略（IFT + DPO）

## 7. AI审稿

**选题眼光**：问题真实——"野生条件语音生成"是 TTS 走向实际应用的必经之路。但选题更多是工程驱动而非认知驱动：更大的数据、更统一框架、更完善的后训练，每一步都"正确"但没有一步让人意外。

**方法成熟度**：架构设计保守，基本是 CosyVoice 2 的放大版。FSQ 换 VQ 是合理的工程选择但不是方法突破。DPO 替代 PPO 也是趋势使然。整体是"巧劲不多，蛮力为主"。

**实验诚意**：100 万小时数据的消融做得扎实，跨语言、跨方言的测试覆盖面广。但有几个问题：
- DPO 的偏好信号来自自动指标，缺乏人类评估验证
- 和 Seed-TTS 的对比用的是对方论文报告的数字而非复现，公平性存疑
- 跨语言克隆的 WER 偏高，论文没有深入分析失败案例

**写作功力**：方法部分写得清楚，但缺少对失败模式的分析。100 万小时数据怎么清洗、怎么过滤、哪些数据被丢弃了——这些工程细节对复现至关重要，但论文一笔带过。

**判决**：==weak accept==——扎实的工程工作，数据规模令人印象深刻，但方法层面没有新发现。"放大即有效"的结论重要但不令人兴奋。
