# PROEMO: 基于提示词的情绪与强度控制的语音合成

- **来源**: arXiv:2501.06276v1
- **作者**: Shaozuo Zhang, Ambuj Mehrish, Yingting Li, Soujanya Poria
- **发表**: arXiv 2025
- **读取日期**: 2026-04-14

---
## 1. 研究背景与问题

**核心问题**：现有表达性语音合成（expressive TTS）方法在控制情绪（emotion）和情绪强度（intensity）方面存在明显缺陷。具体而言：

1. **情绪控制的粒度不足**：多数方法仅支持离散情绪类别（如愤怒、快乐、悲伤、惊讶），无法捕捉情绪的连续变化（nuanced emotions）。
2. **情绪强度建模困难**：强度是情绪表达的关键维度，但现有数据集缺乏强度标注，且强度本身是高度主观和连续的，难以离散化处理。
3. **多说话人表达性语音生成**：在跨说话人迁移情绪时，保持语音自然度和说话人一致性是额外挑战。

**已有方法的局限**：
- **基于辅助特征的方法**（如 VUS、基频、能量等）通过操控声学特征间接控制强度，但效果有限，因为强度与声学特征之间并非简单线性映射。
- **基于插值/缩放的方法**（如 EmoDiff、StyleTTS 2 等）通过插值或缩放隐空间向量来改变强度，但缺乏可解释性，且容易引入 artifacts。
- **基于 LLM 的方法**（如 PromptTTS、InstructTTS）利用自然语言提示控制风格，但大多只关注风格描述，未显式建模情绪强度；且 LLM 输出具有不稳定性，导致生成的韵律参数（pitch, energy, duration）波动较大。

**本文切入点**：
将 LLM 的推理能力引入韵律控制流程。核心假设是：**如果让 LLM 以自然语言提示为条件，推理出可解释的韵律缩放因子（scaling factors），再通过这些因子指导声学模型的 prosody predictor，就能在保持语音自然度的同时，实现细粒度的情绪和强度控制**。

>[!important] 关键设计：LLM 不直接生成语音或声学特征，而是作为"决策器"输出 pitch/energy/duration 的全局（global）和局部（local）缩放因子，再由 FastSpeech 2 的 variance adaptor 执行修改。

## 2. 方法概述

### 2.1 整体架构

**模块说明**：

| 模块 | 输入 | 输出 | 作用 |
|------|------|------|------|
| **TTS Backbone** (FastSpeech 2) | 音素序列、说话人嵌入 | Mel-spectrogram | 基础语音合成，提供可解释的韵律预测能力 |
| **Emotion Encoder** | 参考音频 | 情绪嵌入 (256-d) + 情绪类别 logits | 提取情绪表征，用于条件化和分类监督 |
| **Intensity Encoder** | 参考音频 | 强度标量值 (0-1 连续) | 将强度建模为情绪的连续属性 |
| **Prompt Controller** (GPT-4) | 自然语言提示 | pitch/energy/duration 的全局和局部缩放因子 | 将高层语义意图转化为低层韵律修改指令 |

**设计动机**：
- 选择 **FastSpeech 2** 而非端到端扩散/流模型，是因为其 variance adaptor 中的 pitch/energy/duration predictor 天然支持"可解释修改"——可以直接用缩放因子乘到预测值上。
- 选择 **HuBERT** 作为情绪/强度编码器的基础，是因为自监督语音表征能捕获丰富的韵律和情绪信息，且预训练权重提供了良好的初始化。
- 引入 **GPT-4** 作为提示控制器，是为了利用 LLM 的常识推理能力，将模糊的自然语言描述（如"稍微愤怒一点"）映射为具体的数值缩放策略。

### 2.2 训练策略

训练分为两个阶段：

**阶段一：预训练**
- 在 LibriTTS 上预训练多说话人 FastSpeech 2 骨干网络。
- 使用 GE2E 说话人验证模型提取说话人嵌入。

**阶段二：微调**
- 在 ESD（Emotional Speech Database）上微调，该数据集包含 350 条话语、10 名说话人、5 种离散情绪（Angry, Happy, Neutral, Sad, Surprise）。
- 冻结 FastSpeech 2 的卷积层，只更新 transformer 层、分类/回归头以及新加入的情绪/强度编码器。
- 使用 LLM（GPT-4）预测韵律缩放因子，通过 OpenAI API 调用。

**损失函数**：
- FastSpeech 2 的标准损失（Mel L1, duration MSE, pitch MSE, energy MSE）
- 情绪分类交叉熵损失（监督 Emotion Encoder 的判别能力）
- 强度回归 MSE 损失（监督 Intensity Encoder）

### 2.3 Prompt 控制机制

这是本文最具特色的设计。LLM 接收一个结构化的 prompt 模板，包含：
- 任务描述（控制韵律以匹配目标情绪和强度）
- 输出要求（预测 pitch, energy, duration 的全局和局部缩放因子）
- 决策步骤说明（要求 LLM 逐步推理）

LLM 输出一组缩放因子，通过以下公式修改 variance adaptor 的预测值：

```
d'_i = d_i · G_d · l_{d,i}
e'_i = e_i · G_e · l_{e,i}
p'_i = p_i + G_p + l_{p,i}
```

其中：
- `d_i, e_i, p_i` 为 FS2 variance adaptor 原始预测的 duration, energy, pitch
- `G_d, G_e, G_p` 为全局（global）缩放因子，控制整体情绪基调
- `l_{d,i}, l_{e,i}, l_{p,i}` 为局部（local）缩放因子，对单个词进行微调
- 对于 energy 和 duration，采用乘法缩放；对于 pitch，采用加法偏移（因为 pitch 的感知敏感度更高，乘法容易过度扭曲）

**缩放因子的取值范围**：
- `G_d, G_e ∈ [0.5, 2.0]`（减半到翻倍）
- `G_p ∈ [-5, 5]` semitones
- 局部因子 `l` 的取值范围与全局因子相同

>[!important] 论文发现：duration 对缩放最敏感，energy 次之，pitch 需要更保守的调整。这一经验性发现直接体现在取值范围的设计中。

### 2.4 强度编码器的设计

强度编码器与情绪编码器结构类似（HuBERT + 回归头），但训练目标不同：

1. **相对排序标注**：由于 ESD 数据集没有现成的强度标注，作者借鉴 [23] 的方法，采用**相对属性标注（relative attribute labeling）**。具体而言，对同一说话人的同一情绪类别，计算其 openSMILE 声学特征与 neutral 语音的距离，通过 SVM 学习一个排序函数。
2. **连续值输出**：排序函数的分数被归一化到 [0,1] 区间，作为强度的伪标签（pseudo-label），用于监督强度编码器的回归训练。
3. **按说话人/情绪分离建模**：为每个说话人的每种情绪分别学习排序函数，以消除说话人基线和情绪类别间的混淆。

- [?] 这里有一个隐含的假设：同一说话人、同一情绪类别下的声学特征差异主要由强度引起。但 ESD 数据集中同一情绪的话语数量很少（约 70 条/情绪），样本量是否足以支撑可靠的相对排序？论文未讨论此问题。

## 3. 核心概念

### 3.1 Prompt Control（提示控制）

**定义**：Prompt Control 是本文提出的两层韵律调控机制。LLM 根据自然语言提示，输出 pitch/energy/duration 的全局和局部缩放因子，再由这些因子直接修改 FastSpeech 2 variance adaptor 的预测值。

**与相关概念的关系**：
- 与 **PromptTTS / InstructTTS** 的区别：PromptTTS 将文本提示编码为风格嵌入，再注入 TTS 模型；本文的 Prompt Control 是"显式因子调控"，LLM 输出的是可直接解释的数值指令，而非隐式嵌入。
- 与 **直接声学特征操控** 的区别：传统方法手动设计规则（如"愤怒 = 提高 pitch"）；本文通过 LLM 的常识推理自动推导缩放策略，更具灵活性。

**消融验证**：
- 表 1 显示，加入 prompt control 后，FS2 的情绪分类准确率（ECA）从 24.7%（无控制）提升到 82.0%（全局+局部控制），MCD 从 7.160 降至 6.767，WER 从 0.135 降至 0.129。
- 人类主观实验（图 3）显示，参与者能在 72% 的情况下正确识别带 prompt control 生成语音的强度级别（Low/Medium/High）。

**边界**：
- LLM 的稳定性是关键瓶颈。论文提到早期直接用自由格式 prompt 时，GPT-4 输出不稳定，导致 pitch/energy/duration 剧烈波动。通过设计结构化 prompt 模板和强制逐步推理才缓解。
- 依赖 LLM 的常识是否总是正确？对于某些文化特定的情绪表达（如某些语言中悲伤表现为低声慢速），LLM 的西方中心偏见可能引入偏差。

### 3.2 Intensity Encoder（强度编码器）

**定义**：强度编码器是一个基于 HuBERT 的回归网络，将输入语音映射为一个 [0,1] 区间的连续标量，表示情绪强度。

**与相关概念的关系**：
- 与 **离散强度标签**（如 Low/Medium/High）的区别：强度编码器输出连续值，避免了人为切分阈值的问题。
- 与 **声学特征直接回归** 的区别：不是直接从 openSMILE 特征回归强度，而是先让 HuBERT 学习高层表征，再用回归头映射，利用了自监督预训练的先验知识。

**消融验证**：
- 表 1 中 `FS2_{E/Enc}`（带情绪编码器）vs `FS2_{E/Enc+I/Enc}`（同时带情绪和强度编码器）的对比显示，加入强度编码器后，MCD 从 6.619 降至 5.594，WER 从 0.127 降至 0.125，MOS 从 3.194 提升到 3.728。这说明强度编码器显著改善了合成语音的自然度和可懂度。
- 图 4 的 t-SNE 可视化显示，强度嵌入在情绪类别内部形成了清晰的从弱到强的梯度结构，验证了编码器确实学到了强度相关的连续变化。

**边界**：
- 训练依赖"相对排序"生成的伪标签，如果排序函数本身有偏，误差会传播到强度编码器。
- 只在 ESD 的 5 种情绪上验证，对于更复杂的情绪（如羞愧、厌恶）或更微妙的强度变化，泛化能力未知。

### 3.3 Global vs. Local Prompt Control（全局与局部控制）

**定义**：全局控制（global）调整整句话的韵律基调；局部控制（local）针对每个词分别调整缩放因子，实现更细粒度的情感表达。

**消融验证**：
- 表 1 显示，`FS2_{E/Enc+I/Enc}` 在"无 prompt"、"仅全局"、"全局+局部"三种设置下的 ECA 分别为：74.8% → 77.1% → 82.0%。局部控制带来了约 5% 的显著提升。
- 这说明某些情绪表达需要在特定词语上加重或减轻，全局统一的缩放不足以捕捉这种词级别的韵律变化。

**边界**：
- 局部控制将词级别的缩放因子直接作用于 variance adaptor 的输出，但 FastSpeech 2 的 duration predictor 是在音素级别预测的，词与音素的对齐可能引入粒度不匹配的问题。
- 论文未展示局部控制是否会引入"过度戏剧化"或不自然的韵律断裂。

## 4. 核心洞见

**一句话洞见**：
> 将 LLM 从"风格描述生成器"重新定位为"可解释韵律因子的推理器"，可以在不修改 TTS 骨干网络架构的前提下，通过显式的数值缩放实现细粒度、可迁移的情绪与强度控制。

**展开**：
本文的方法论价值不在于提出了新的 TTS 架构，而在于展示了一种"**分层控制**"的新范式：高层语义意图（自然语言提示）→ 中层可解释因子（LLM 推理的缩放值）→ 低层声学修改（variance adaptor 执行）。这种分层解耦使得：
1. TTS 模型可以专注于语音质量，无需承担风格理解的责任；
2. LLM 的推理结果人类可读、可调试；
3. 控制逻辑与合成模型分离，便于迁移到其他 TTS 骨干上。

## 5. AI审稿评价

### 5.1 选题价值

**真缺口还是人造缺口？**

这是一个**真实且紧迫**的问题。表达性 TTS 在虚拟助手、有声书、游戏配音等场景中有强烈需求，而情绪和强度的细粒度控制一直是瓶颈。已有方法要么只控制离散情绪，要么控制强度时缺乏可解释性。本文同时解决"情绪+强度+自然语言提示"三个维度，选题有价值。

### 5.2 方法贡献

**方法论层面的新发现，还是工程组合？**

更接近**已知技术的工程组合**，但组合方式有新意：
- FastSpeech 2 + HuBERT 编码器 + GPT-4 提示控制，这三个组件都是已有技术。
- 新贡献在于"Prompt Control"这一接口设计——将 LLM 输出约束为具体的缩放因子，并通过结构化 prompt 模板稳定化输出。
- 创新点的**不可替代性中等**：如果换用其他 LLM（如 Claude、Llama）或其他 TTS 骨干（如 VITS、NaturalSpeech 2），核心思路仍然成立，说明方法具有一定通用性。

### 5.3 实验严谨性

**优点**：
- 使用了客观的声学/感知指标（MCD, WER, CER, ECA）和主观 MOS/PQR 测试。
- 消融实验比较了"无控制/仅全局/全局+局部"三种设置，以及"仅情绪编码器/情绪+强度编码器"两种配置，较为系统。

**不足**：
- **Baseline 选择偏少**：只与 Duff-Exprt 和基础 FS2 对比，未与同期更先进的表达性 TTS 方法（如 EmoDiff、StyleTTS 2、NaturalSpeech 2）对比。
- **数据集规模小**：ESD 只有 350 条话语、10 名说话人、5 种情绪，且只有英语。结论的泛化性存疑。
- **缺乏跨语言/跨说话人泛化实验**：论文声称支持多说话人，但实验主要在 ESD 的有限说话人上进行，未展示对未见说话人的零样本迁移能力。
- **LLM 成本与延迟未讨论**：每次推理都要调用 GPT-4 API，实时部署的可行性未评估。
- **强度标注的可靠性**：基于 openSMILE + SVM 的相对排序是启发式的，其生成的伪标签质量未经过人工验证。

### 5.4 写作质量

- **优点**：结构清晰，方法描述详尽，公式和图示配合得当。Figure 2 对 prompt 控制流程的图解非常直观。
- **不足**：
  - 某些关键细节缺失：如 GPT-4 的具体 prompt 内容未完整披露（只展示了模板框架）；
  - 对 LLM 输出不稳定性的描述一带而过，未给出量化分析；
  - 结论部分过于简短，未充分讨论局限性和未来方向。

### 5.5 判决

**Weak Accept**

**理由**：选题有价值，Prompt Control 的接口设计有新意，实验在有限范围内支持了核心主张。但 baseline 覆盖不足、数据集规模小、LLM 部署成本未讨论，限制了工作的普适性和工程价值。作为一篇 5 页的短文（可能是 workshop 投稿），内容密度尚可，但若要冲击主会，需要补充更多对比实验和跨域验证。

## 6. 启发

### 迁移

**Prompt Control 的分层控制思想可以迁移到其他生成任务中**。例如：
- 在歌声合成（SVS）中，可以用 LLM 将"更激昂"的提示转化为 pitch bend 和 dynamics 的缩放因子，再由声码器执行；
- 在可控视频生成中，可以用 LLM 将"镜头推进"的提示转化为相机参数的 delta 值，再由渲染引擎执行。

**具体接法**：保留底层生成模型的结构不变，在其"可解释的中间表征"（如 TTS 中的 duration/pitch/energy，视频中的相机参数）和 LLM 之间建立一座"因子桥"。

### 混搭

**将 PROEMO 的 Prompt Controller 与端到端 TTS（如 CosyVoice、Seed-TTS）组合**：
- 端到端模型音质更好，但可控性弱；
- 可以用 PROEMO 的 LLM 输出作为"软约束"，通过 classifier-free guidance 或 latent manipulation 注入到端到端模型的解码过程中；
- 产出：兼具高自然度和细粒度可控性的表达性 TTS 系统。

### 反转

**论文的假设**：LLM 的常识推理足以正确映射"情绪描述→韵律修改"。

**反转思考**：这个假设是否总是成立？如果 LLM 对某种情绪的常识理解与目标文化/个体不一致，就会产生系统性偏差。这意味着：
- **该停下什么**：不要盲目信任 LLM 的零样本推理结果用于语音控制；
- **该开始什么**：收集人类对"情绪-韵律映射"的偏好数据，用 RLHF 或 DPO 微调一个专门的"韵律决策小模型"，替代通用的 GPT-4，可能更稳定、更可控、成本更低。

1. **首次将 LLM 作为"韵律缩放因子推理器"**，而非风格嵌入生成器，提升了控制的可解释性；
2. **显式建模情绪强度为连续属性**，并通过相对排序解决无标注数据的训练问题；
3. **提出全局+局部两层 prompt 控制**，在词级别实现更细粒度的韵律调整。
